# 사용자 협업 패턴

## 요구사항 단계적 축소

사용자는 큰 그림을 던진 뒤 대화로 점점 좁혀가는 방식을 선호. 첫 응답에 모든 것을 담는 것보다 **갭 분석 → 결정 옵션 제시 → 좁히기**의 사이클로 가는 게 효과적.

**Why**: gugbab-voca PRD 작성 과정에서 "말해보카 같은 앱" → "음성·실시간 제외" → "SRS도 빼고" → "다시 SRS·IndexedDB 도입"으로 요구사항이 여러 번 변경됨. 처음부터 모든 결정을 받으려 하지 않고 단계적으로 받는 게 사용자 사고 흐름과 맞음.

**How to apply**:
- AskUserQuestion으로 한 번에 2~3개 결정만 받기
- 모호한 영역은 추천안과 함께 옵션 제시
- 사용자가 다음 답변에서 "사실 이건 빼고" 하는 식의 변경에 유연하게 대응

## 정리/제거 작업의 보수 원칙

"사용할 수도 있는 건 남겨두고 진짜 불필요한 것만 제거"가 명시 원칙.

**Why**: 2026-05-08 리포지토리 정리 요청 시 "진짜 불필요한 것만"이라고 강조함. 사용 가능성이 1%라도 있으면 유지가 기본 입장.

**How to apply**:
- 명백히 무관한 것만 제거 후보로 분류 (gugbab-voca의 경우 학술/도덕교육/백엔드 카테고리)
- 모호한 항목은 자동으로 유지하고, 따로 "모호 영역" 섹션에 명시해 사용자가 추가 결정할 수 있게
- destructive 작업은 분류표 먼저 보여주고 명시 승인 받은 후 실행

## 외부 작업 분담

스킬·에이전트 생성 같은 작업을 다른 환경(`01_gugbab-claude-package` 등)에서 처리하고 결과만 본 프로젝트로 가져오는 워크플로우 사용. 본 프로젝트에서는 명세 작성·통합·정리에 집중.

**How to apply**: 신규 스킬·에이전트 생성 요청이 와도 본 프로젝트에서 직접 만들지 말고 명세 문서로 정리해 외부 전달용으로 작성. 단, 사용자가 본 프로젝트에서 만들라고 명시 지시하면 따름.

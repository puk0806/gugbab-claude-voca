# 커밋·푸시 전 작업 보고 필수

**규칙**: 코드 작성·문서 작성 등 작업이 끝나면 **commit/push 직전에 멈춰서** 다음을 보고한다. 사용자 승인 후에만 commit/push 실행.

**Why**: 2026-05-10 사용자 명시. 작업 내용을 사용자가 검토할 기회 없이 commit이 진행되면 의도와 다른 산출물이 git history에 박힘. 1인용이라도 검토 단계 분리 필요.

**How to apply**:

## 보고 형식 (필수 항목)

```
## 작업 보고

### 변경 파일 목록
- 추가: path/to/file.ext (요약)
- 수정: path/to/file.ext (어떤 부분)
- 삭제: path/to/file.ext (이유)

### 핵심 변경 내용
- 결정 1
- 결정 2
- 결정 3

### 미해결·후속 항목 (있을 경우)
- ❓ 사용자 결정 필요 항목들
- 다음 PR로 미룬 항목들

### 다음 액션 제안
- 커밋 메시지 초안: `[type] Subject`
- PR 제목 초안
- 머지 후 다음 단계

→ 사용자 승인 대기
```

## 적용 범위

- 모든 git commit 직전
- 모든 git push 직전
- 모든 PR 생성 직전
- 메모리만 수정한 경우는 *예외* (휘발성 영역)
- 실수 정정·오타 수정 같은 사소 변경도 보고 후 진행

## 안티패턴 (하지 말 것)

- 작업 → 곧바로 commit → 보고: ❌ 사용자 검토 기회 없음
- 작업 → 보고 + commit 동시 실행: ❌ 승인 전 commit
- 보고 누락하고 push: ❌ 명시적 위반
